## Compatibility decisions to preserve

- The formula supplies the CLI, daemon and browser UI. The optional app supplies the native
  window and menu bar. App-only installations remain supported.
- The app attaches to a **running compatible daemon using the same data**, via discovery
  protocol 1. Merely installing a stopped formula does not make it own the daemon. When no
  daemon is listening, the app starts its bundled worker.
- Quitting an attached app leaves the independent daemon running. Quitting an app that owns
  its worker stops that worker. A disconnected attached app waits and reconnects without
  starting a competing daemon.
- Formula and cask are updated independently. When attached, the formula daemon serves the
  web UI and determines its version. The cask does not create a CLI link. Upgrade a desktop
  bundle as a whole; never let the standalone updater replace its embedded helper.
- The new cask preserves shared Application Support data, including on `--zap`. The old
  beta.9 cask did not: migrate with a normal cask upgrade, without resetting or deleting data.
- Existing formula users upgrade and restart the formula before adding the optional app.
  Existing beta.9 cask users upgrade the cask before installing the formula, so the old cask
  releases its CLI link. See [desktop installation and migration](../desktop.md).
- Preserve release asset names, checksum verification, version ordering and discovery
  compatibility. The updater reads the release list because `/releases/latest` excludes
  prereleases. Do not delete old releases, move published tags, or replace published assets.
- Build CLI artifacts before desktop artifacts (`bun run build:release`); the CLI build clears
  `dist/`. Generate both Homebrew definitions from those final artifacts. Verify all six assets
  in a draft, publish them, then promptly publish both tap definitions together.

## Passed verification

- 168 automated tests; typecheck and diff checks.
- Browser checks for responsive cards/logs, fixed header/navigation, independent scrolling,
  keyboard dialog focus, draft retention, validation, busy-button dimensions and reduced motion.
- Apple Silicon and Intel CLI/native builds; all four helpers report beta.10. Intel executables
  ran under Rosetta. Both app signatures verify.
- The exact final native bundle passed WebKit loading/live polling, child crash recovery, child
  cleanup after host exit, existing-service attachment, reconnection and service survival after Quit.
- The published beta.9 executable discovered beta.10, verified and installed the actual candidate

- After publication, the unchanged beta.9 executable discovered beta.10 through the real public
  GitHub API. The beta.10 executable reported itself up to date.
- An actual Homebrew cask upgrade from beta.9 to beta.10 removed the old cask CLI link and retained

- Actual formula beta.9 installation after the cask upgrade, followed by formula upgrade to beta.10,

- Cask uninstall with `--zap` removed the app while an independently launched Homebrew-installed
  formula daemon stayed alive. The formula CLI and shared test data survived.
- Fresh formula-first, app-second installation succeeded after the uninstall test.
- All six uploaded asset digests matched the final build. All six published assets subsequently
  downloaded without authentication and matched local SHA-256 values.
- Remote main/tag and tap main were checked after publication.

## Isolation and remaining limits

Homebrew package tests used a separate prefix and app directory. Test-only definitions redirected
URLs to the real local release archives, omitted external dependencies, redirected zap paths to
disposable data, and used a harmless test bundle ID for the quit target. Production tap definitions
retain their dependencies and normal bundle ID. Runtime checks used isolated Autopilot/gh data,
disabled notifications and did not install a login service or alter the user's working installation.

The apps are ad-hoc signed, not notarized. Physical Intel hardware, downloaded-app Gatekeeper
approval, interactive OAuth, notifications and Open at Login still require manual testing, as
disclosed in the release notes. Rosetta emitted Bun's AVX warning; it is not a substitute for Intel
hardware validation. These are recorded beta limitations, not unfinished publication steps.
